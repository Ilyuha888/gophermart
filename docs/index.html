Gophermart — how it works

Loyalty points service. The design as decided on 2026-11-27; the code follows it PR by PR.

A shop wants its regular buyers to come back. Each purchase earns points; points pay for later purchases, 1 point = 1 unit of local currency. Gophermart is the buyer's points account: it knows whose order is whose, how many points each order earned, and how many were spent.

🧑
Buyer

Registers in Gophermart, buys in the shop, hands Gophermart the number of the order, spends points.

🛒
Online shop

Sells and issues order numbers. Not built here: the task treats it as given.

🧮
Accrual system

Accrual means the points credited for an order. This system is the shop's calculator: it decides how many points an order earns, by rules that may change any time, and tells only the number, not why. It takes its time and limits how often we may ask. Given as a binary.

🐹
Gophermart (we build)

Links order numbers to buyers, asks the accrual system about each order until it has an answer, keeps the balance, records spending.

The journey

  1. 1RegisterThe buyer gets a Gophermart account.ours
  2. 2Buy in the shopAn order with a number.assumed, not built
  3. 3Order reaches accrualThe shop passes it to the calculator.accrual system's job
  4. 4Upload the numberThe buyer tells Gophermart “this order is mine”. Only now does the order have an owner on our side.ours
  5. 5Check with accrualGophermart keeps asking until the answer is final: points, or none.ours
  6. 6Credit pointsA positive answer adds points to the balance.ours
  7. 7Spend pointsThe buyer pays part or all of a new order with points.ours

    Balance (computed, D4)

    current = Σ orders.accrual (PROCESSED) − Σ withdrawals.sum
    withdrawn = Σ withdrawals.sum

    Measured on local Postgres: 0.87 ms for a user with 100 orders, 18 ms with 100 000 (research/balance-cost.sql).
